# AI Review

## Assignment Overview

This document captures the review criteria and expectations for the submission.

## 4. Your Task

Choose one scenario and create something that materially improves the situation.

The scenario may contain several visible problems. You are not expected to solve all of them.

You must decide:
- What you believe the most important problem is
- Who you are solving it for
- What assumptions you are making
- What you will build within the available time
- What you will deliberately leave out

We are not prescribing the format, interface, technology, or type of solution.

A narrow, coherent and functional submission is better than a large collection of incomplete features.

## 5. Deliverables

Submit one folder or repository containing the following:

1. README
   Keep the README to a maximum of one page. It should explain:
   - Which scenario you selected
   - The problem you chose to address, in your own words
   - Who the primary user is
   - What you chose not to solve and why
   - The assumptions you made
   - How your solution works from beginning to end
   - How to run or view it
   - What you would do with five additional hours

   Include one simple sketch, diagram or flow showing how the solution works.

2. Working Demonstration
   Submit at least one of the following:
   - A deployed link
   - A runnable repository
   - A prototype with functional interactions
   - A three-to-five-minute screen recording

   A screen recording is acceptable when deployment would consume a disproportionate amount of time.

   The demonstration should show the main experience working from beginning to end.

## 6. Evaluation Criteria

We will evaluate the submission across the following dimensions:

| Dimension | What we will assess |
| --- | --- |
| Problem understanding | Did you identify a meaningful underlying problem rather than reacting only to the most visible symptom? |
| Prioritisation | Did you make deliberate choices about what to solve first? |
| Scope discipline | Is the submission appropriately sized for the available time? |
| User understanding | Does the solution reflect the actual environment, abilities and constraints of its users? |
| Practical adoption | Could the solution realistically fit into the existing workflow? |
| Product judgment | Do the decisions form a coherent and useful experience? |
| Working execution | Does the core flow function well enough to demonstrate the idea? |
| AI judgment | Did you critically review, correct and direct AI-generated work? |
| Communication | Can another person clearly understand the problem, decisions and solution? |

We are not evaluating:
- Production-grade architecture
- Extensive test coverage
- Pixel-perfect visual design
- A large number of features
- The use of a particular framework
- Whether the solution is ready for commercial deployment
